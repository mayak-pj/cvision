# Сборка портативного дистрибутива для Windows 7

Рабочий компьютер: **Windows 7 x64 SP1, без прав администратора, без интернета**.
Поэтому на нём ничего не устанавливается: программа, Python и библиотеки лежат в одной папке,
которую переносят флешкой.

Собирать нужно **на компьютере с Windows и интернетом** (версия Windows значения не имеет).

## Два способа собрать

**1. На GitHub Actions** (когда репозиторий будет опубликован) — ничего скачивать вручную не нужно.
Вкладка Actions → «Портативная сборка для Windows 7» → Run workflow. Раннер сам скачает
embeddable Python и библиотеки, соберёт папку и выложит её артефактом
`photo-renamer-windows7-portable`. Его остаётся скачать и распаковать на флешку.

Почему это работает, хотя раннер — Windows Server: сборка ничего не компилирует, а только
раскладывает по папкам готовые файлы (embeddable Python 3.8.10, колёса `cp38`/`win_amd64`,
tkinter от 3.8.10). Совместимость с Windows 7 определяют именно они, а не система сборки.

**Чего Actions не заменит:** раннеров с Windows 7 у GitHub нет, поэтому проверить фактический
запуск можно только на рабочей машине — `check_install.py` (шаг 4 ниже).

**2. Вручную на любой Windows-машине с интернетом** — дальше по шагам.

## Что скачать (на машине с интернетом)

| Что | Где | Зачем |
|---|---|---|
| `python-3.8.10-embed-amd64.zip` | python.org → Downloads → Windows → Python 3.8.10 → *Windows embeddable package (64-bit)* | сам Python, без установки |
| `python-3.8.10-amd64.exe` | там же, *Windows installer (64-bit)* | только ради файлов tkinter: в embeddable-версии его нет |
| библиотеки | командой ниже | numpy, scipy, Pillow |

Python 3.8.10 — последняя версия с поддержкой Windows 7.

## Шаг 1. Библиотеки

```bat
python dist_offline\download_wheels.py --dest dist_offline\wheels
```

Скачает колёса **именно для Python 3.8 и 64-битной Windows** (`cp38`, `win_amd64`),
даже если сам скрипт запущен на другой версии Python. Проверьте список в конце вывода.

## Шаг 2. Файлы tkinter

Установите `python-3.8.10-amd64.exe` (обычная установка, можно «только для меня» —
права администратора не нужны). Запомните папку установки, например
`C:\Users\Вы\AppData\Local\Programs\Python\Python38`.

Оттуда берутся: `DLLs\_tkinter.pyd`, `DLLs\tcl86t.dll`, `DLLs\tk86t.dll`, `Lib\tkinter`, `tcl`.
Копирует их сборщик, вручную ничего делать не нужно.

`DLLs\zlib1.dll` копируется, если он есть: в установке с python.org он присутствует,
а в некоторых сборках (например, у раннеров GitHub) его нет, и tkinter работает без него.
После копирования сборщик проверяет, что все обязательные файлы на месте.

## Шаг 3. Сборка

```bat
python dist_offline\build_portable.py ^
    --embed python-3.8.10-embed-amd64.zip ^
    --wheels dist_offline\wheels ^
    --tk-from "C:\Users\Вы\AppData\Local\Programs\Python\Python38" ^
    --out "D:\Переименование фото"
```

Сначала полезно посмотреть план без записи: добавьте `--dry-run`.

Что делает сборщик:
1. распаковывает embeddable Python в `python\`;
2. правит `python38._pth`, чтобы работали библиотеки и код программы;
3. распаковывает колёса в `python\Lib\site-packages` (колесо — это zip, pip на рабочей машине не нужен);
4. копирует файлы tkinter из обычной установки Python;
5. копирует `src\`, `run.py`, примеры настроек, создаёт `logs\` и `cache\`;
6. кладёт ярлыки запуска и инструкцию для пользователя.

## Шаг 4. Проверка на машине сборки

```bat
"D:\Переименование фото\python\python.exe" "D:\Переименование фото\check_install.py"
```

Проверяются версия Windows и Python, библиотеки, окно (tkinter), чтение JPEG, запись в `logs`
и `cache`, настройки. Все строки должны быть «ок».

## Шаг 5. Перенос

Скопируйте папку целиком на флешку и оттуда — на рабочий компьютер, например в
`C:\Users\<пользователь>\Переименование фото` или на любой диск, где есть право записи.
Запуск **не из сетевой папки**: программа пишет рядом с собой логи и кэш.

На рабочем компьютере повторите шаг 4, затем запускайте `Переименование фото.bat`.

## Размер и требования

- Дистрибутив: примерно 120–150 МБ (Python ~15 МБ, numpy ~25 МБ, scipy ~60 МБ, Pillow ~3 МБ, tkinter ~10 МБ).
- Кэш миниатюр и признаков растёт по мере работы, ограничен настройкой `cache_max_mb` (по умолчанию 2 ГБ).
- Права администратора не нужны ни на одном шаге на рабочей машине.
- Компонент Universal C Runtime на рабочей машине уже есть (проверено: `C:\Windows\System32\ucrtbase.dll`).
  Если на другой машине его не окажется, программа не запустится — тогда рядом с `python.exe`
  нужно положить файлы UCRT (`ucrtbase.dll` и `api-ms-win-crt-*.dll`) из Windows SDK.

## Если что-то не работает

| Признак | Причина и что делать |
|---|---|
| Окно не открывается, в консоли `No module named _tkinter` | не скопированы файлы tkinter: соберите с `--tk-from` |
| `DLL load failed` при запуске | колёса не для `cp38`/`win_amd64` — пересоберите список библиотек (шаг 1) |
| Программа закрывается сразу | запустите «Запуск с консолью (для ошибок).bat» — текст ошибки останется на экране |
| `check_install.py` ругается на запись в `logs` | папка только для чтения: перенесите программу туда, где есть право записи |

Файлы `wheels/`, распакованный Python и готовые архивы в git не попадают (см. `.gitignore`).

## Почему не один .exe

Такой вариант возможен (PyInstaller), но для этой задачи он хуже:

- **Версии.** PyInstaller 6 и новее требует Windows 8 и выше. Для Windows 7 годится только
  ветка 5.x с Python 3.8 — то есть ещё одна устаревшая зависимость, которую никто не поддерживает.
- **Один файл — медленный запуск.** Вариант «всё в одном .exe» при каждом запуске распаковывает
  около 120 МБ во временную папку. На рабочем компьютере временная папка может быть закрыта
  политиками, и запуск будет заметно дольше.
- **Антивирусы.** Собранные PyInstaller файлы часто попадают под ложные срабатывания.
  На машине без интернета и без прав администратора разбираться с этим тяжело.
- **Выгоды почти нет.** Вариант «папка с файлами» (PyInstaller onedir) — это ровно то же,
  что уже собирается сейчас, только без лишнего слоя. Пользователь так же копирует папку
  и запускает ярлык, а настройки, список категорий и журналы остаются обычными файлами,
  которые можно открыть и поправить.

Если единый файл всё же понадобится (например, так принято в вашей организации), добавить
задачу сборки .exe в Actions несложно — скажите, и я сделаю.
