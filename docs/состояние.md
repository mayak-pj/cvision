## Что уже работает

- Анализ проекта: папки сравниваются между собой, похожие объединяются в группы,
  для каждой группы нужен свой эталон. Готовые эталоны определяются по именам файлов.
- Редактор эталона: сетка миниатюр (названные — по именам, неназванные — по съёмке следом),
  масштаб Ctrl+колесом, двойной клик — фото крупно, список категорий с поиском и кнопками
  «+»/урна, число ракурсов, автопереименование (Ctrl+S), отмена (Ctrl+Z). Сочетания работают
  в любой раскладке и на macOS через Command.
- Пакетное переименование группы: предпросмотр «текущее имя → новое», крупные фото
  (размер настраивается), кандидаты, клавиши 1 и 2 — выбрать кандидата, 3 — не переименовывать,
  сортировка щелчком по заголовкам столбцов, свои категории (+ и урна у списка),
  Enter — подтвердить и вниз, Ctrl+Z — отменить правку, журнал и откат.
- Имя предлагается каждому фото (`always_propose`), сомнительные помечены «ПРОВЕРЬТЕ»;
  переименовывается всё, кроме помеченных «не переименовывать».
- Распознавание: цвет без фона, текстура, контуры + **CLIP** (если подключена модель).
  Раскладка — венгерский алгоритм с учётом состава эталона, правило сторон, правило серий,
  нумерация по порядку съёмки.
- Портативная сборка: embeddable Python 3.8.10 + библиотеки + tkinter + onnxruntime 1.11.1
  + библиотеки Visual C++ + модель CLIP.

## Что проверить на целевой машине

Всё сделанное 26 сентября проверено только на macOS. На Windows 7 другой шрифт, другая
клавиатура и сетевые диски, поэтому перед передачей коллегам нужно посмотреть:

1. **Галочка «✓» в столбце «Эталон»** — это знак шрифта. В этом проекте уже было, что
   `✓` и `🗑` в tkinter на Windows 7 не отображаются (поэтому «плюс» и урна рисуются).
   Если вместо галочки квадрат — заменить на знак попроще или вернуть слово.
2. **Сочетания в русской раскладке**: Ctrl+S, Ctrl+Z, Ctrl+A в редакторе эталона и
   Ctrl+C/V/X в полях ввода. На Windows клавиша узнаётся по коду; логика проверена тестами,
   но ни одного настоящего нажатия на Windows не было. Заодно — при **включённом NumLock**
   (из-за него привязки с Command на Windows не ставятся вовсе).
3. **Ширина столбцов и размер окна** при крупном системном шрифте: и то и другое теперь
   считается по шрифту, окно при открытии само раздвигается под столбцы.
4. **Порог «почти все детали эталона»** (`FINISHED_COVERAGE`, сейчас 0.9). Нужны настоящие
   числа: `python tools\folder_status.py <папка> --reference <эталон>` по двум папкам,
   у которых статус выглядел неправильно.
5. **Список категорий чистится сам**: мусор `file (1)…file (17)` должен исчезнуть из
   `names.txt` при первом запуске новой сборки.
6. **Эталон с латинской `C`**: файлы «Cтойка многопозиционная фото 1/2.JPG» на диске остались
   с ней. В списке категорий имя уже правильное, а файлы чинятся повторным переименованием
   этих двух фото.

После этого — собрать артефакт (GitHub Actions, workflow «build-windows») и передать
заказчику на флешке. Коммиты 26 сентября пока только локальные, не отправлены.

## Как проверять

Тесты интерфейса создают настоящие окна Tk, и без настроек прогон мешает работать
за машиной: питон с Tk становится обычной программой macOS, выходит на передний план
и сворачивает полноэкранное окно браузера на рабочий стол — за прогон десяток раз.
Поэтому `tests/conftest.py` после создания первого окна ставит процессу политику
активации NSApplication «Prohibited» (вперёд он больше не выходит) и делает каждое окно
полностью прозрачным. Окна при этом живут как обычно — размеры, фокус, нажатия клавиш.
Свои временные скрипты с окнами стоит начинать так же: `sys.path.insert(0, "tests")`
и `import conftest`. Проверить со стороны:

```bash
for i in $(seq 1 30); do lsappinfo info -only name "$(lsappinfo front)"; sleep 0.5; done
```

во время прогона впереди должна оставаться программа пользователя, а не `python`.

```bash
.venv/bin/python -m pytest -q                      # тесты
.venv/bin/python run.py --groups <папка проекта>   # анализ групп
.venv/bin/python run.py --reference <эталон> <папка>   # проверка без переименования
.venv/bin/python tools/evaluate_labels.py --reference <эталон> logs/разметка/<файл>.xlsx
.venv/bin/python tools/folder_status.py <папка> [<папка> ...]   # почему у папки такой статус
.venv/bin/python dist_offline/check_install.py     # состояние сборки, включая модель CLIP
.venv/bin/python scripts/check_before_push.py      # перед публикацией
```

Снимок имён для отката испытаний:

```bash
.venv/bin/python tools/snapshot_names.py check   tests/test_photos --snapshot "logs/снимок имён до испытаний.csv"
.venv/bin/python tools/snapshot_names.py restore tests/test_photos --snapshot "logs/снимок имён до испытаний.csv"
```

## Правила, которые нельзя нарушать

- **Фотографии из `tests/test_photos/` не должны попадать в интернет** — это реальные рабочие
  данные. Папка в `.gitignore`, в отчётах и коммитах описывается только структура и цифры.
- Единственный шаблон имён — «Категория N фото K». Отклонения в данных — это ошибки оператора,
  а не второй формат.
- Деление серии на экземпляры по паузам между кадрами не используется: пауза между разными
  деталями бывает такой же короткой, как между сторонами одной.
- Обрабатываются только файлы `.jpg` (в любом регистре). `.jpeg`, `.png`, `.tif` не трогаются,
  файлы со словом «рентгенограмма» в имени пропускаются.
- Программа только переименовывает файлы внутри их папки: ничего не удаляет, не перемещает
  и не изменяет содержимое фотографий.
- Рабочая машина: Windows 7 x64 SP1, Python 3.8, без интернета и прав администратора.
  Зависимости: Pillow, NumPy, SciPy, tkinter, onnxruntime (необязательно).
