# Photo Renamer — переименование фотографий комплектующих по эталону

Настольное приложение для Windows, которое переименовывает фотографии компьютерных
комплектующих в папках с серийными номерами. Образцом служит эталонная папка,
переименованная вручную.

> Статус: программа работает целиком; собирается портативный дистрибутив для Windows 7.
> Осталось: проверка сборки на рабочей машине и настройка порогов по её результатам.
> Инструкция для конечного пользователя появится на этапе 7.

## Как это работает (кратко)

1. Пользователь вручную переименовывает одну папку с фото — это **эталон**:
   `Процессор 1 фото 1.jpg`, `Процессор 1 фото 2.jpg`, `Материнская плата фото 1.jpg`,
   `Оперативная память 1 фото 1.jpg`, `Кулер.jpg`, `Кабель HDMI.jpg`, …
2. Программа строит признаки каждого эталонного фото (perceptual hash + цветовая гистограмма)
   и разбирает имена в структуру «категория → экземпляр → сторона».
3. В целевых папках (рекурсивно в папке проекта) каждое фото сопоставляется со «слотами»
   эталона оптимальным назначением (венгерский алгоритм). Стороны одной детали идут
   подряд, и число сторон берётся из эталона. Экземпляры нумеруются по порядку появления.
4. Сначала показывается **предпросмотр** (текущее имя → новое имя, % уверенности)
   с возможностью ручной правки, и только после подтверждения выполняется `os.rename`.
5. Лог и отчёт сохраняются **рядом с программой** в `logs/`, а не в обрабатываемых папках.

## Правила обработки файлов

| Файлы | Поведение |
|---|---|
| `.jpg` / `.JPG` (любой регистр) | обрабатываются |
| `.jpeg`, `.png` | **не трогаются** (используются для других целей) |
| прочие форматы | игнорируются |
| имя содержит «рентгенограмма» (любой регистр) | полностью пропускаются, в статистике не учитываются |

- Используется только `os.rename` внутри той же папки. Файлы **никогда** не удаляются,
  не перемещаются и не перезаписываются: содержимое фото остаётся нетронутым.
- Неопознанные фото сохраняют исходное имя и попадают в отчёт с топ-кандидатами.
- Переименование можно откатить по CSV-логу.

## Ограничения целевого окружения

- Windows 7 x64 SP1, i5-6500, 16 GB RAM, **без прав администратора и без интернета**.
- Фото лежат на сетевых дисках, около 15 МБ каждое. В папке от 1 до 250 фото, папок от 1 до 1000+.
- Python 3.8.10 embeddable (последняя версия с поддержкой Windows 7) + офлайн-wheel-файлы.
- Зависимости: Pillow, NumPy, SciPy (`linear_sum_assignment`), tkinter. Без нейросетей и облачных API.
- Обработка строго последовательная, без потоков и процессов.

## Окно программы

```bat
python run.py
```

1. Укажите папку проекта и нажмите «Анализировать». Программа найдёт все папки с фото
   (на любой глубине вложенности), сравнит их и объединит похожие в группы.
2. Для каждой группы предлагается эталон: готовый (папка уже названа по шаблону)
   или папка с наибольшим числом фото, которую нужно переименовать вручную.
3. Папку можно перенести в другую или новую группу и выбрать другой эталон.
   «Сходство с эталоном» подсказывает, насколько папка похожа на эталон своей группы.
4. Первое чтение фото медленное (файлы читаются по сети целиком), повторное — быстрое
   благодаря кэшу `cache\` рядом с программой.

## Редактор эталона

Открывается кнопкой «Создать / изменить эталон…» для выбранной группы.

- **Слева** — миниатюры папки в порядке съёмки. Размер меняется Ctrl+колёсиком или кнопками
  «+»/«−», двойной щелчок открывает фото крупно (стрелки листают, Esc закрывает).
- **Выделение** как в Проводнике: щелчок, Ctrl+щелчок, Shift+щелчок, рамка мышью, Ctrl+A.
- **Справа** — список категорий с поиском: каждое введённое слово ищется по началу любого слова
  в названии («оп пам» → «Плата оперативной памяти»), «ё» и «е» не различаются.
  Имена можно добавлять и удалять.
- **Ракурсы** — сколько фото приходится на одну деталь. Значение подставляется само:
  программа помнит его для каждой категории и берёт из готового эталона проекта.
- **«Переименовать выделенные»**: выделенные фото делятся по числу ракурсов на экземпляры,
  нумерация продолжает уже существующие. Ctrl+Z отменяет последнее переименование.
  Всё пишется в лог в `logs\`.

Имена категорий хранятся в `names.txt` рядом с программой (образец: `names.example.txt`).

## Точность

- Если **состав папки совпадает с эталоном** (столько же фото), программа требует точного
  совпадения количеств по категориям и предлагает имя каждому фото. На размеченной папке
  из реального проекта: **97% имён верны** (133 из 137).
- Фото, в которых программа не уверена, помечаются «ПРОВЕРЬТЕ». Все ошибки попадают в эту
  пометку: на размеченной папке это 36 фото из 137, и среди них все 4 ошибки. Просмотр
  примерно четверти фото в предпросмотре даёт 100% верных имён.
- **Исправления распространяются:** когда вы задаёте категорию вручную, раскладка всей папки
  пересчитывается. На проверенных данных это вдвое сокращает число ручных правок.
- Порядок фото берётся по дате съёмки (EXIF), а не по имени файла: на порядок опираются
  правила сторон и нумерации. Если порядки расходятся, программа предупреждает.
- Если состав папки отличается от эталона, точность заметно ниже. Тогда для такой группы
  папок нужен свой эталон — это видно в первом окне.

## Переименование папок группы

Кнопка «Переименовать папки группы…» в первом окне (доступна, когда эталон группы готов).

- Папки обрабатываются по одной: «Папка X из Y», прогресс чтения фото.
- **Предпросмотр:** таблица «текущее имя → новое имя» с миниатюрой, % уверенности и состоянием
  («распознано», «по правилу сторон», «НЕ УВЕРЕНА», «НЕ ПОХОЖЕ НИ НА ЧТО»).
- **Сомнительные строки идут первыми** (переключатель «Сомнительные — первыми»), есть фильтр
  «показать только требующие проверки». Так проверка занимает четверть времени вместо полного просмотра.
- **Правка с клавиатуры:** встаньте на строку в таблице и нажмите **1**, **2** или **3** —
  фото получит соответствующего кандидата, а выделение перейдёт к следующей строке.
  **0** (или Delete) — не переименовывать это фото.
- **Правка мышью:** выберите строки и нажмите кандидата («1 — Кулер — 47%») или категорию из списка
  справа (поиск такой же, как в редакторе эталона). Можно выделить сразу несколько строк.
  После каждой правки раскладка всей папки пересчитывается, номера экземпляров обновляются.
- **«Переименовать папку»** выполняет переименование после подтверждения, показывает отчёт
  (% распознанных, расхождения с эталоном, неопознанные, проблемные категории) и предлагает
  перейти к следующей папке. «Отменить эту папку» возвращает исходные имена.
- Всё пишется в CSV-лог и TXT-отчёт в `logs\`.

## Консольный режим

```bat
rem Проверка без переименования: отчёт на экране и в logs\
python run.py --reference "Z:\Проект\Эталон" "Z:\Проект"

rem Переименование: по каждой папке показывается отчёт и задаётся вопрос [д/н]
python run.py --reference "Z:\Проект\Эталон" "Z:\Проект" --apply

rem Анализ проекта: группы похожих папок и какие эталоны нужны
python run.py --groups "Z:\Проект"

rem Откат по логу запуска
python run.py --rollback "logs\2026-09-18_14-30-05_Проект.csv"
```

- Обрабатываются все папки с фото внутри указанных путей. Эталон пропускается, даже если лежит внутри проекта.
- Логи пишутся в `logs\` рядом с программой. Каждый запуск даёт два файла:
  CSV-лог (открывается в Excel) и TXT-отчёт. Имена начинаются с даты и времени и включают имя папки.
  В каждой строке CSV есть полный путь к обработанной папке.
- Настройки — `config.json` рядом с программой. Образец с пояснениями: `config.example.json`.

## Портативная сборка для Windows 7

Рабочая машина без интернета и без прав администратора, поэтому ничего не устанавливается:
Python, библиотеки и программа лежат в одной папке, которую переносят флешкой.

Собирается на любой машине с Windows и интернетом:

```bat
python dist_offline\download_wheels.py --dest dist_offline\wheels
python dist_offline\build_portable.py --embed python-3.8.10-embed-amd64.zip ^
    --wheels dist_offline\wheels --tk-from "C:\...\Python38" --out "D:\Переименование фото"
"D:\Переименование фото\python\python.exe" "D:\Переименование фото\check_install.py"
```

Либо без единой команды: вкладка **Actions** → «Портативная сборка для Windows 7» → Run workflow.
Раннер соберёт всё сам и выложит артефакт `photo-renamer-windows7-portable`
(`.github/workflows/build-windows.yml`). Раннеров с Windows 7 у GitHub нет, поэтому
запуск на рабочей машине всё равно проверяется через `check_install.py`.

Подробно, с объяснением каждого шага и разбором частых ошибок: [dist_offline/README.md](dist_offline/README.md).
Инструкция для конечного пользователя кладётся в дистрибутив: `dist_offline/Инструкция.txt`.

## Оформление

Кнопка-лампочка в главном окне переключает оформление: горит — светлое (как в Windows 7),
погашена — тёмное. Выбор запоминается в `config.json` (`"theme": "light" | "dark" | "system"`).

## Проверка перед публикацией

Репозиторий рассчитан на публикацию, поэтому рабочие данные в него не попадают:
фото, логи, таблицы разметки, кэш, `config.json` и `names.txt` исключены в `.gitignore`.

```bash
python scripts/check_before_push.py
```

Скрипт проверяет файлы под версионным контролем и сообщения коммитов: запрещённые типы файлов
(фото, сканы, логи, таблицы), сетевые пути Windows, IP-адреса, почту на непубличных доменах
и слова-маркеры. Находки печатаются с замаскированной серединой, код возврата ненулевой.

Свои конфиденциальные слова (организация, изделия, серверы, фамилии) держите
в `scripts/sensitive_terms.local.txt` — этот файл не версионируется.
Публикуемый `scripts/sensitive_terms.txt` содержит только пояснения и примеры.

Чтобы проверка выполнялась автоматически перед каждым `git push`:

```bash
cp scripts/pre-push .git/hooks/pre-push && chmod +x .git/hooks/pre-push
```

Хуки не версионируются, поэтому команду нужно выполнить в каждой копии репозитория.
Разовый обход при ложной тревоге: `git push --no-verify`.

## Разработка

Работа ведётся по этапам, каждый этап — отдельный коммит:

0. Структура репозитория ✅
1. Файловая система: поиск папок с фото, фильтры, сортировка ✅
2. Признаки (pHash, гистограмма) и разбор имён эталона ✅
3. Сопоставление (венгерский алгоритм, пары сторон, нумерация, пороги) ✅
4. Переименование, dry-run, CSV-лог, отчёт по категориям, откат ✅
5. GUI на tkinter: первое окно ✅, редактор эталона ✅, пакетное переименование ✅
6. Интеграционное тестирование и настройка порогов
7. Офлайн-дистрибутив и инструкция для пользователя ✅
